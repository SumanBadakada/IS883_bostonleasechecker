# IS883_bostonleasechecker

**Boston Lease Checker**, IS883 Fall 2026, Team 4. A Streamlit app for a BU graduate student signing
a first Greater Boston lease: upload the lease (text-based PDF or DOCX) and get each clause flagged
*lawful*, *unusual* or *possibly unlawful* under Massachusetts tenant law, with a citation, plus a check
of the move-in charges against the legal limits.

Live app: https://bostonleasechecker.streamlit.app/

> Not legal advice. Output is generated by a language model and may be wrong.

## Run it locally

```bash
pip install -r requirements-dev.txt
cp .streamlit/secrets.toml.example .streamlit/secrets.toml   # then paste your Gemini API key
streamlit run app.py
```

On Streamlit Community Cloud, put `GEMINI_API_KEY` in **App settings → Secrets**. Never commit a key.

## How it works

See [`docs/architecture.md`](docs/architecture.md) for the diagram.

| Capability (§5.1) | Where it fires |
| --- | --- |
| Structured prompting | `leasecheck/prompts.py`: versioned `PROMPTS["v1"]` / `["v2"]` |
| Tool calling | `leasecheck/charges.py: check_move_in_charges`, called by Gemini through `llm.run_with_tools` |
| Retrieval | `leasecheck/retrieval.py`: embeddings over `sources/`, top passages per clause |
| Structured output | `leasecheck/schemas.py: BatchFindings`, with a retry-then-"could not be checked" failure path |

**Interface:** an Overview tab with "questions to ask your landlord", a clause review that shows the cited
law, the full lease with problem clauses highlighted, a move-in cost table, a follow-up chat, a
downloadable printable report (`leasecheck/report.py`), and a one-click sample lease
(`samples/sample_lease.docx`, rebuilt by `python scripts/make_sample_lease.py`). Developer options
(prompt version, retrieval on/off, token counts) appear only at `<app-url>/?dev=1`.

Other required behaviour: per-session cap (`config.MAX_ANALYSES_PER_SESSION`, `MAX_CHAT_MESSAGES_PER_SESSION`)
in `st.session_state`; key in Streamlit secrets; a visible disclaimer; scanned, empty, non-lease and
oversized files rejected before any model call; API errors retried, then shown as a message.

## Layout

```
app.py                     Streamlit UI (theme in .streamlit/config.toml)
samples/                   fictional sample lease for the "Try a sample lease" button
leasecheck/                parsing, retrieval, prompts, schemas, charges tool, Gemini client, pipeline
sources/                   legal source notes (see sources/README.md: must be verified)
scripts/fetch_sources.py   downloads the official texts to check the notes against
eval/                      clause bank, test-set builder, labelling guide, eval runner, metrics
tests/                     offline unit tests (fake model, no API key needed)
docs/                      architecture diagram, suggested ownership split
```

## Tests and evaluation

```bash
python -m pytest                      # offline, no key needed
python -m eval.build_test_set         # regenerates eval/test_set/ (20 leases + 3 awkward inputs)
export GEMINI_API_KEY=...
python -m eval.run_eval --limit 2     # develop on two inputs first
python -m eval.run_eval --prompt-version v1   # "before"
python -m eval.run_eval --prompt-version v2   # "after"
```

`run_eval` reports recall on possibly-unlawful clauses (the planned headline metric), overall
agreement, a confusion matrix, deterministic checks (JSON parse failures, flags with a citation,
correct citation, tool called with the right rent and deposit, rejected inputs handled as expected),
and average tokens per lease for the cost model. Results go to `eval/results/`.
